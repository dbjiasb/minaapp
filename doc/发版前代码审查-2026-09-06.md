## P1：发版前应修复

### 1. WebView 向任意页面提供登录凭证

- 位置：[web_view.dart:197](/Users/roll/Dokai/Code/minaapp/biz/lib/base/webview/web_view.dart:197)。
- `getUserInfo` 桥直接返回 `ApiService.base()`，其中包含 `_tokens` 中的登录 token 和 uid。所有 WebView 都注册该桥，导航没有来源白名单，返回数据前也不校验当前页面来源。
- 触发：应用内网页通过链接或重定向进入第三方页面后，该页面调用桥即可读取登录凭证；无需原生权限。路由 `handleRoute` 接受 HTTP URL，WebView 也未限制后续导航。
- 修复：凭证桥仅用于明确可信的 HTTPS 来源；每次调用和异步回传都校验当前来源。通用网页只暴露必要的非敏感资料。

### 2. Android 消耗型内购先消费后验单，失败后没有可靠补单记录

- 位置：[payment_service.dart:375](/Users/roll/Dokai/Code/minaapp/biz/lib/business/purchase/payment_service.dart:375)。
- `buyConsumable` 使用默认 `autoConsume: true`。本地安装的 `in_app_purchase_android 0.5.0` 在向业务层交付购买事件前调用 `consumePurchase`，因此后面的 `verified && pendingCompletePurchase` 无法保护消耗型商品。
- 触发：用户付款后，服务端验单连续两次超时或进程退出。商品已经消费，`cachedReceipts` 又没有写入这笔订单的路径，重启时无法依靠当前补单代码恢复，可能出现扣款但未到账。
- 修复：Android 关闭自动消费，先持久化账号、订单和 receipt，服务端幂等发货成功后再消费；为验单和消费分别保留重试状态。iOS 按其插件要求处理，不能直接照搬 Android 参数。

### 3. 本地聊天存储未完整隔离账号，会覆盖会话并跨账号删除消息

- 位置：[chat_session_handler.dart:43](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/chat_session_handler.dart:43)、[chat_message_handler.dart:125](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/chat_message_handler.dart:125)。
- 会话表只以 `id` 为主键，而私聊 id 是对方用户 id；`upsertSession` 使用 replace。账号 A、B 在同一设备与同一角色聊天，B 的写入会直接覆盖 A 的会话行。SQLite 最小复现确认 A 的查询结果变为空。
- 此外，“从这里重新开始”调用的 `deleteMessagesFromId` 只有 sessionId 和消息 id 条件，没有 ownerId，会删除另一个账号同一角色的后续消息。
- 修复：使用 `(ownerId, id)` 会话主键，并迁移现有数据库；所有读取、更新、删除操作统一限定 ownerId，不能只修改建表 SQL。

### 4. 账号切换后，旧聊天同步响应会写进新账号

- 位置：[chat_manager.dart:289](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/chat_manager.dart:289)、[chat_message.dart:298](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/chat_room_cells/chat_message.dart:298)。
- 同步请求等待期间可以退出并登录另一个账号；`onLogout` 只停止定时器，没有使在途请求失效。响应回来后，消息 ownerId 和会话 ownerId 都取“当前账号”，同步游标的持久化键也取当前账号。
- 结果：A 的消息可能进入 B 的数据库视图，A 的游标可能写到 B 名下，导致隐私串号和消息漏拉。对实际 `ChatMessage.fromServerData` 的临时测试确认 ownerId 跟随切换后的账号。
- 修复：请求捕获账号及登录会话代次，响应处理和每段异步落库前检查；退出时取消或失效化在途同步，清理账号相关的内存状态。`AccountService.queryMyInfo` 等异步更新也存在同类模式，应一并处理。

### 5. 真人拨号返回计费文案时抛出 TypeError

- 位置：[controller.dart:391](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/call/controller.dart:391)。
- `costDescTitle` 声明为 `RxString`，但将服务端 JSON 字符串直接赋给它。只要 `costOrEarnContent` 非空，就抛出 `String` 不能赋给 `RxString` 的异常，中断后续引擎初始化。
- 修复：写入 `costDescTitle.value`，并对返回类型做规范化。最小 Flutter 测试已确认该赋值抛错。

### 6. 正式包持久化并上传含登录凭证的日志

- 位置：[api_service.dart:118](/Users/roll/Dokai/Code/minaapp/biz/lib/base/api_service/api_service.dart:118)、[account_service.dart:253](/Users/roll/Dokai/Code/minaapp/biz/lib/core/account/account_service.dart:253)。
- release 分支每十次请求将完整 body 交给 `L.i`，包含 token、uid 和业务内容；Google 登录还直接记录 accessToken、idToken。`AppLog` 使用 ProductionFilter 和 FileOutput，随后支付失败、客服消息等流程会自动压缩上传这些日志。
- 结果：网络层加密前的凭证及聊天等业务数据进入持久化文件和日志存储，扩大凭证暴露范围。
- 修复：日志入口统一脱敏；正式包只记录方法、状态码、耗时和非敏感关联 id，移除 OAuth、RTC token 以及完整请求体。

### 7. 发布签名密钥和口令同时进入 Git

### 8. 正式构建脚本固定了不可用/不满足版本约束的 SDK

- 位置：[build_aab_dis.sh:5](/Users/roll/Dokai/Code/minaapp/dis/build_aab_dis.sh:5)、[build_ios_dis.sh:5](/Users/roll/Dokai/Code/minaapp/dis/build_ios_dis.sh:5)。

## P2：应在本次发布前处理的功能问题

### 9. 商品不可用后购买锁不释放

### 10. 通话关闭后连接超时定时器继续执行

- 位置：[controller.dart:182](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/call/controller.dart:182)。
- `close` 仅取消 countingTimer，未取消进房和断线超时计时器；`onClose` 同样没有取消。用户在连接中挂断并返回其他页面后，30 秒定时器仍调用 `endCall`，其第一句无条件 `RouteHelper.back()`，会关闭用户当时所在页面，还可能操作之后新建的全局通话。
- 修复：关闭和销毁时取消全部计时器、移除消息监听，并让结束逻辑幂等且只作用于所属 callId。

### 11. 视频匹配任务把 JSON Map 当成对象读取

- 位置：[match_service.dart:140](/Users/roll/Dokai/Code/minaapp/biz/lib/business/discovery/services/match_service.dart:140)。
- `matchTaskCache` 来源于响应 JSON Map，`mainTaskProcesses` 却通过 `.finishStatus` 访问；当子任务非空且主任务存在时，会抛出 NoSuchMethodError，影响 `video_match_view` 中任务区域构建。
- 修复：按 Map 键读取状态或先反序列化成明确的 model。最小 Flutter 测试已确认 JSON Map 不能通过此 getter 读取字段。

### 12. 语音消息解锁使用视频免费次数

- 位置：[chat_manager.dart:453](/Users/roll/Dokai/Code/minaapp/biz/lib/business/chat/chat_manager.dart:453)。
- voice 分支读取 `freeVdoLeftTimes`，但账号模型分别维护 `freeAdoLeftTimes` 和视频次数。用户语音次数尚余、视频次数耗尽时，会提交 `usePrem=0`；反向情形会错误申请会员解锁。
- 结果可能是本可免费使用的语音被请求按普通方式扣费，或服务端拒绝不符合额度的会员解锁；实际扣费结果取决于服务端校验。
- 修复：语音分支使用语音额度，并覆盖两类额度分别耗尽的场景。
